# 元素反应系统

一把枪，按 `Q` 在 **火 / 水 / 冰** 之间循环。命中敌人时先写入元素附着，再查表结算反应：
蒸发 / 融化走伤害乘区，冻结 / 碎冰走状态路径。实现刻意拆成两个互不越界的层，
新增反应只需扩规则表，不必改底层计时或冻结逻辑。

---

## 1. 分层结构

| 层 | 组件 / 文件 | 只负责 | 明确不负责 |
|---|---|---|---|
| 元素附着层 | `UCandyFightElementAuraComponent` | 记录“有什么元素、还剩多少 GU、每秒衰减多少”、维护 `Element.*` 标签 | 查反应表、算伤害、冻结 |
| 反应结算层 | `UCandyFightElementReactionComponent` + `UCandyFightReactionRules` | 读“旧附着 + 新元素”，查表得到反应、倍率、双方 GU 消耗，分发到伤害或状态路径 | 计时衰减、冻结表现 |
| 冻结状态层 | `UCandyFightFrozenEffectComponent` | 冻结时长、禁用移动/射击、冰霜材质实例、Niagara 寒气、受击提前解冻/碎冰 | 伤害乘区、附着衰减 |

伤害入口是 `TakeDamage`：弹道事件携带 `Element` / `ElementGauge`，敌人和靶子先调用
`ElementReactions->SettleHit(...)`，拿回 `FinalDamage` 再扣血。调用方不需要知道任何反应细节。

文件：

```
Source/TPSdemo/CandyFight/Elements/
    CandyFightElementTypes.h/.cpp        枚举、附着记录、反应结果、原生 GameplayTag、显示辅助
    CandyFightReactionRules.h/.cpp       规则行 FCandyFightReactionRule + 规则集 UCandyFightReactionRules
    CandyFightElementAuraComponent.h/.cpp      附着层
    CandyFightElementReactionComponent.h/.cpp  反应结算层
    CandyFightFrozenEffectComponent.h/.cpp     冻结状态层
Source/TPSdemo/CandyFight/Tests/CandyFightElementReactionTests.cpp  自动化测试
```

## 2. 附着层（Aura）

- 数据结构：`TMap<ECandyFightElement, FCandyFightAuraEntry>`，每条记录 `Gauge`（GU）与 `DecayPerSecond`。
- 自然衰减：1U ≈ 9.5 秒，2U ≈ 12 秒；施加时按当时的 GU 一次性算好速率
  （`GetDecaySeconds`：1U 以下按比例，1U 以上每多 1GU +2.5 秒，上限 `MaxAuraGauge = 2U`）。
- 同元素重复命中会叠加并夹到上限；不同元素可短暂共存（例如反应后残留的触发元素）。
- GU 归零自动移除，并清掉对应 `Element.*` 标签、广播 `OnAuraExpired`。
- 时间基准是游戏时间（`AdvanceTo(World->GetTimeSeconds())`），暂停/时间回退不会倒扣。

可调参数（组件上）：`SecondsPerGauge`、`AdditionalSecondsPerGauge`、`MaxAuraGauge`、
`bShowAuraLabel`（世界空间 `FIRE 1.0U` 文字，没有美术资源也能看见附着）。

**头顶元素光球**：每个附着元素生成一个按元素着色的球（火橙红 / 水蓝 / 冰青），
左右并排、随镜头朝向排列，附着消失时自动隐藏；远距离也能一眼看出怪身上带什么元素。
参数：`bShowAuraOrbs`、`AuraOrbSize`、`AuraOrbHeight`、`AuraOrbSpacing`。

## 3. 反应层（Reaction）

### 3.1 规则表

`UCandyFightReactionRules` 是 DataAsset（相当于设计文档里的 `DT_ReactionRules`），
未指定资产时使用类默认值，内置三行：

| 元素 A | 元素 B | 反应 | A 触发 B 的倍率 | B 触发 A 的倍率 | 消耗 |
|---|---|---|---|---|---|
| 火 | 水 | 蒸发 | 1.5（火打水） | 2.0（水打火） | 1:1 对消 |
| 火 | 冰 | 融化 | 2.0（火打冰） | 1.5（冰打火） | 1:1 对消 |
| 水 | 冰 | 冻结 | — | — | 清空附着，冻元素量 = 消耗量 ×2 |

每行字段：`MultiplierATriggersB` / `MultiplierBTriggersA`、`AuraCostPerGauge`、
`TriggerCostPerAura`、`bConsumeAllAura`、`FreezeSeconds`、`FreezeGaugeMultiplier`、`FlatDamageBonus`。

调参：新建一个 `UCandyFightReactionRules` 资产，改完赋给敌人 / 靶子的
`ElementReactions->Rules` 即可；测试 `CandyFight.Elements.RuleAssetOverride` 覆盖了这条路径。

### 3.2 结算流程（`SettleHit`）

1. **冻结中**：
   - 火 → 按冰附着走融化（默认 ×2.0）并立即解冻（碎裂表现）；
   - 物理（`None`）→ 累计破冰伤害，达到 `BreakDamageThreshold` 时提前解冻；
   - 冰 / 水 → 不产生新反应。
2. **常规**：取当前最强附着元素，与新元素无序匹配规则表。
   - 蒸发 / 融化：`伤害 = 基础伤害 × 倍率 + FlatDamageBonus`，按 1:1 消耗双方 GU；
     触发元素若有剩余，自动作为新附着留下。
   - 冻结：清空附着，计算冻元素量（消耗量 ×2）并调用冻结组件，不改伤害。
   - 同元素 / 无匹配：只叠加附着，伤害不变。
3. 结算后写入 `Reaction.*` 标签（默认 0.75 秒）、`LastReaction`，广播 `OnReaction`，
   并在目标上方显示 `VAPORIZE x1.5` / `MELT x2.0` / `FREEZE` / `SHATTER` 飘字。

## 4. 冻结层（Frozen）

`UCandyFightFrozenEffectComponent`：

- `Freeze(Seconds, Gauge)`：加 `State.Frozen`（含 `Reaction.Freeze`）标签、禁用 `CharacterMovement`、
  `StopFire()`/`ClearExternalFireRequest()` 停止开火、给网格挂动态材质实例染色、
  （可选）挂 Niagara 寒气、显示 `FROZEN 1.7s` 世界文字。
- `Unfreeze(bShatter)`：逆向恢复移动模式、材质和标签；（可选）播放碎裂特效。
- `NotifyDamage(Damage)`：冻结期间累计物理伤害，超过阈值立即解冻并让反应层记为 `Shatter`。
- 基础冻结 2 秒（规则表可改）；冻元素量约为被消耗附着量的 2 倍。
- 三个可选资源槽：`FreezeEffect`、`ShatterEffect`、`FrostMaterial`，
  不配置时仍然有材质染色和状态文字，配置后即为冰雾/碎冰/冰霜覆盖表现。

## 5. 枪械与输入

- `UCandyFightCombatComponent::CurrentElement`：默认玩家为火，AI 的枪为物理（`None`）。
- `Q` 键：`BindInput` 绑定、`InitializeLocalPlayer` 把 `Q` 注入玩家专属的输入映射副本
  （不修改共享的 IMC 资产，也不要求新建 InputAction 资产；指定 `ElementSwitchAction` 则使用该资产）。
- 切元素时：枪身三个网格的动态材质实例改 `Color` 参数、广播 `OnElementChanged`、HUD 状态行显示
  “火 / 水 / 冰 · Q 切元素 · R 装填…”。
- 当前项目同时有 6×6 背包：`Q` 切元素、`E` 拾取、`B` 开背包、`ESC` 关背包，互不冲突。
- 弹道在**开火瞬间**快照元素与 GU；之后切元素不会改变在飞的子弹。
- 控制台调试：`ElementTestSwitch 1|2|3`（火/水/冰），其他值循环；`WeaponTestEquip` 仍可用。

## 6. GameplayTag

原生标签（无需 `DefaultGameplayTags.ini`，随模块注册）：

- 附着：`Element.Fire`、`Element.Water`、`Element.Ice`
- 反应：`Reaction.Vaporize`、`Reaction.Melt`、`Reaction.Freeze`、`Reaction.Shatter`
- 状态：`State.Frozen`

查询入口：`Aura->ActiveTags`、`Reactions->ActiveReactionTags`、`Frozen->StateTags`。

## 7. 与 GAS 的对应关系

本项目没有启用 GameplayAbilities 插件，因此没有套 GAS 的 AttributeSet/GE/ExecCalc；
但层边界与设计文档一致，后续要迁 GAS 时可以逐层替换：

| 设计文档 | 本项目实现 |
|---|---|
| 附着层维护 GU 与 GameplayTag | `UCandyFightElementAuraComponent` |
| DT_ReactionRules 组合匹配 | `UCandyFightReactionRules`（DataAsset，内置默认行） |
| GameplayEffectExecutionCalculation 算最终伤害 | `UCandyFightElementReactionComponent::SettleHit` 返回 `FinalDamage` |
| GE Spec 的 SetByCaller 传反应类型/倍率 | `FCandyFightReactionHit`（伤害事件里也带 `Element`/`ElementGauge`） |
| FrozenEffectComponent | `UCandyFightFrozenEffectComponent` |

## 8. 扩展新反应（超载 / 感电）

1. 在 `ECandyFightReaction` 增加枚举值，在 `CandyFightElementTypes.cpp` 补名字/颜色/标签；
2. 在规则资产里加一行（例如 火 + 雷 → 超载）；
3. 如果它属于“状态类”反应，按冻结组件的方式新增一个独立状态组件，并在 `SettleHit`
   的两条路径里各接一处；如果是“伤害类”，只填倍率/固定伤害字段即可。

不需要改附着层的计时、衰减或标签逻辑。

## 10. 已知简化

- 每帧每目标的合并伤害只结算一次附着/反应（霰弹多颗弹丸同帧命中视为一次）。
- 没有元素精通、抗性、等级压制等原神数值项；蒸发/融化直接乘规则表倍率。
- 冻结时长固定 2 秒（规则表可改），未实现原神冻元素随冻结时间加速衰减的精确公式。
- 冻结的染色以动态材质实例实现；`M_EnemyBody` 没有暴露颜色参数，因此敌人主要靠
  `FROZEN` 状态文字、停火/停走和可选 Niagara 表现；配置 `FrostMaterial` 后才能看到冰霜覆盖。

## 11. 实机验证（PIE）

1. 打开 `Content/CandyFight/Maps/L_CandyFight`，点击 Play（Alt+P）。
   出生点 `(-4400,-600)`，正前方约 5.6 米就是 200 HP 的靶子 `(-3840,-590)`；这张图没有敌人。
2. 操作：`WASD` 移动、鼠标瞄准、左键开火、`R` 换弹、`Q` 切元素。
   右下角 HUD 显示“火/水/冰 · Q 切元素 · R 装填…”，枪身颜色随元素变化。
3. 半自动枪 20 伤害，靶子 200 HP。命中后靶子头顶会亮起**元素色光球**并显示 `FIRE 1.0U` /
   `VAPORIZE x1.5` 之类的世界文字：

| 操作 | 预期 |
|---|---|
| 默认火打一发 | 180 HP，`FIRE 1.0U`；同元素再打一发叠到 2U，约 12 秒后消失 |
| 水附着 → 火打（Q 到水打一发，再按两次 Q 回火） | `VAPORIZE x1.5`，30 伤害，水附着清空 |
| 火附着 → 水打（Q 一次到水） | `VAPORIZE x2.0`，40 伤害，火附着清空 |
| 冰附着 → 火打 | `MELT x2.0`，40 伤害 |
| 火附着 → 冰打 | `MELT x1.5`，30 伤害 |
| 水附着 → 冰打 | `FREEZE`，20 伤害不变，靶子变冰蓝 + `FROZEN 2.0s`，2 秒后恢复 |
| 冻结中火打（冰→火按一次 Q） | `MELT x2.0`，立即解冻 |

4. 测敌人冻结改用 `L_CandyFight_AI_Test`：出生 `(-1000,-1200)`，三个敌人分别在
   `(-1400,-600)`、`(-350,-250)`、`(-1050,950)`，每个 100 HP。水 + 冰冻住后敌人会停止移动和射击，
   2 秒后恢复；火打冻结敌人会融化并解冻。
5. 控制台（`~`）：`ElementTestSwitch 1|2|3` 直接切火/水/冰；`WeaponTestEquip 1|2|3`
   切换半自动/全自动/霰弹，元素不随枪械重置。

注意：`E` 仍是宝箱/撤离门的交互键（`IMC_CandyFightInteract`），元素切换在 `Q`，两者不冲突。
